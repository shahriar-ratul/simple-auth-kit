Rate limiter gets the permission cache's swap contract

Done
Before 
// auth.service.ts — concrete class injected directly,
// confirmed in every variant of every combo:
@Inject(InMemoryRateLimitStore)
private readonly rateLimit: InMemoryRateLimitStore,
// No config field, no swap point, silently
// worse than PermissionCache's DI-token pattern.
After 
// NestJS combos — mirrors PERMISSION_CACHE_STORE exactly:
@Inject(RATE_LIMIT_STORE)
private readonly rateLimit: RateLimitDeps,
// Express combos — no DI container, so the config
// object is the swap point, mirroring permissionCacheStore:
const rateLimit: RateLimitDeps =
  config.rateLimitStore ?? new InMemoryRateLimitStore();
Verified: all 4 combos' npm run typecheck pass clean (materializes both variants + tsc, no live DB needed). One real deviation surfaced by the compiler itself: Express combos' AuthService constructors also typed the dependency as the concrete class (TS2741 on the interface-typed value otherwise) — not just the NestJS combos as originally suspected. Fixed identically, 4 extra files, documented below.

2What the re-sync surfaced: a real regression

The required CLI re-sync reintroduced a previously-fixed production-build break — found and fixed before this pass was called done

This is the review's "combos are hand-duplicated with no drift detector" risk playing out one level up the stack, in the admin apps rather than the backend combos: apps/admin-react[-workspaces] had drifted ahead of registry/admin-apps/react/* without the fix ever being backported — the exact anti-pattern AGENTS.md already names as a bug ("An example ahead of its combo is a bug"), just for admin apps instead of examples.

1
2026-08-14, commit 9cbda19: a prior hotfix added @fontsource-variable/bricolage-grotesque, shadcn, tw-animate-css to both React admin apps' package.json + 2 lines to each index.css — applied directly to apps/*, never backported into registry/admin-apps/react/*.
2
This session: fixing the stale-comment issue required a CLI add --force --into apps/admin-react re-sync (the repo-documented correct mechanism). Because registry is the CLI's only source of truth, the resync faithfully regenerated package.json and index.css from registry — and silently dropped the font/CSS fix again, reintroducing the exact "production builds were broken" condition commit 9cbda19 existed to fix.
3
Caught, not shipped: the implementing agent flagged the unexpected diff instead of forcing through it or guessing whether it was safe. Traced to commit 9cbda19 via git log/git show, the exact missing lines identified, backported into registry/admin-apps/react/variants/{base,workspaces}/{package.json,src/index.css}, then the 2 CLI re-syncs re-run.
4
Verified for real, not just typechecked: npx vite build run to completion in both apps/admin-react and apps/admin-react-workspaces — both produce a clean production bundle (✓ built in ~3s, no unresolved-import errors), confirming the regression is actually gone, not just type-clean.

This is now permanently fixed at the source (registry), not just patched in the generated app — the next add --force re-sync of either React admin app will carry the font/CSS fix forward instead of dropping it again.
